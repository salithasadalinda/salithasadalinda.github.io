ESP-32 Camera TinyML: What I Learned

Jul 20, 2026 · Embedded AI · ESP-32 · TinyML

The XIAO ESP32S3 Sense is a tiny board with a camera that is genuinely capable of running ML models on-device. These are the hard-won lessons from deploying an Edge Impulse FOMO object detector (cloth counting) and a Teachable Machine image classifier on its integrated OV2640/OV3660 camera.

The camera auto-detects as OV3660, not OV2640

Everyone assumes the Sense uses an OV2640. The esp32-camera driver actually auto-detects it as an OV3660. Trust the driver's detection — hard-coding OV2640 assumptions in your init code causes subtle capture failures that look like wiring problems.

The tensor arena must live in PSRAM

A 96×96 grayscale model needs around 180 KB of tensor arena. That does not fit in the ESP32-S3's internal RAM, so the arena must be allocated with heap_caps_malloc(..., MALLOC_CAP_SPIRAM). Enabling OPI PSRAM in the board settings is non-negotiable: 

CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_SPIRAM_USE_CAPS_ALLOC=y
CONFIG_SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY=y

For the Edge Impulse FOMO model I had to double the tensor arena size by hand — from 182,579 bytes to 365,158 bytes in the generated inferencing header — before the model would allocate all its tensors.

Reference kernels are painfully slow

Running the classifier with TFLite Micro's reference C++ kernels took ~4.6 seconds per frame on the ESP32-S3 — useless for real time. The S3 has no HIFI5 DSP, so the generic XTENSA kernels in tflite-micro give no benefit either.

ESP-NN is the game-changer: 31× faster

Switching to the ESP-IDF framework with Espressif's ESP-NN library replaced the reference conv, depthwise-conv, fully-connected, pooling, softmax, add and mul kernels with hand-tuned assembly for the S3's MAC16/PIE instructions: 

Arduino / reference kernels   ~4600 ms/frame   0.22 FPS
ESP-IDF + ESP-NN               ~147  ms/frame   5.8  FPS   (31x faster)

With capture (~25 ms) plus inference (~147 ms) the total per-frame cost drops to ~172 ms — fast enough for live classification.

Everything is int8 and unsigned-to-signed matters

The exported model is signed int8. Camera frames arrive unsigned, so subtract 128 from each pixel before inference or every prediction is garbage. Frame handling is also critical: capture QVGA (320×240), center-crop, and downscale to the model's 96×96 input rather than letting the camera produce odd resolutions.

Debugging the real problems

  • Flat gray screen — not a code bug, spin the OV7670 lens focus ring.
  • Flash size warning ("expected 8 MB, found 2 MB") — benign on the XIAO ESP32S3.
  • All scores flat — the model was exported without "Embedded model" selected in Teachable Machine.
  • Partition scheme — use "Huge APP (3MB No OTA)" for the FOMO build; models inflate firmware quickly.

Source: cloth-counting-fw and teachable_machine.
