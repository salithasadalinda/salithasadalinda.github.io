ESP-32 Camera Streaming: What I Learned

Jul 20, 2026 · Firmware · ESP-32

Streaming video from an ESP-32 CAM sounds simple — it isn't. Memory is tiny, bandwidth is limited, and a naive server makes the whole board crawl. Here is what I learned building a camera server in Arduino.

Frame buffer strategy

Capture and serve are asynchronous. Grab one frame into a buffer, serve it, then grab the next. Double-buffering stops the camera from stalling while a client downloads.

Compression matters

JPEG is the natural choice, but gzip-compressing static routes keeps the firmware payload small. I moved dashboard assets to gzip-compressed routes served straight from flash — faster boot, fewer bytes.

Keep credentials out

WiFi and API secrets belong in a credentials.h.template that the user copies to credentials.h. The real file is gitignored so keys never leak into version control.

Dashboard

A small JavaScript dashboard displays the MJPEG stream with minimal overhead. Keep the page light — every byte competes with video bandwidth on the same connection.
